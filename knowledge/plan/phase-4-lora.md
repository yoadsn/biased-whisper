# Owner decision

On 2026-11-07 the owner requested a **Phase 4 harness**, independently of
Phases 2N/3. Phase 1 heuristics are considered sufficient pseudo-label signal
to try adapter training, without mass value labeling or a mandatory strict
integer-parser filter. Natural word-style baseline outputs are useful teacher
targets even when suppression changes nothing. Degenerate outputs are excluded.
The owner's estimate of >90% correct Phase 1 cardinal examples is an observation,
not a measured training-set accuracy established by this implementation.

Build the harness and monitoring UI; do not automatically launch the ~20k-clip
experiment. Training is launched explicitly from the UI or normal job registry.

# Procedure

**Parallel cached/DDP is now the default.** See
[parallel Phase 4](/reference/phase4-parallel.md) for the approved multi-GPU
implementation, cache identity, resume, cancellation and validation. The
procedure below describes the still-available legacy `parallel=false` online
mode and the shared training-target semantics.

`phase4` (`src/bwhisper/phase4.py`) runs in the ordinary serial GPU job queue.

1. Load the established `setup_scale` recording-disjoint cohorts (explicit
   `cohort_run`, or latest). Verify all IDs exist and recordings do not overlap.
   Training uses discovery only; do not consume the entire ~20k corpus as
   training at the expense of the existing held-out partition. Exclude all
   current controller campaign confirmation recordings from both training and
   monitoring. Shuffle deterministically, cap by `train_limit`, and freeze a
   one-clip-per-recording monitoring subset before producing predictions.
2. Install LoRA in decoder linear modules; optionally also the final N encoder
   layers. The base checkpoint remains frozen. The implementation is explicit
   PyTorch LoRA (`src/bwhisper/lora.py`), **not PEFT-format**.
3. At each training sample's first encounter, disable all adapter contributions,
   set the base to eval mode, and call Phase 1 `analyse_sample` with built-in
   span-start/prefix/symbol rules. This teacher remains the original checkpoint,
   not the partially trained student. No mutable latest-satellites dependency.
4. Accept complete, nonempty, non-looping, digit-free `cardinal` targets with
   adequate non-number rest-match. Accept natural `no_digits` baseline outputs
   as cardinal or no-number preservation examples, independently configurable.
   Reject partial/no-number-word conversion failures, degeneration, truncation,
   invalid tokens and context overflow. `value_filter=false` by default; opt-in
   conservative numeric agreement may reject valid but unknown forms.
5. Teacher-force the **entire accepted transcript including EOS**, conditioning
   on but not scoring the forced language/task prefix. No digit bans apply to
   the student loss. Full-transcript supervision includes surrounding words,
   but is not a separate KL preservation objective or a correctness guarantee.
6. Use AdamW, gradient accumulation over accepted one-clip microbatches,
   finite-gradient checking, clipping and linear warmup to constant LR. Flush
   remainder accumulation correctly at epoch boundaries. Reuse the first-pass
   targets over 1–3 epochs; they are not regenerated by the adapting student.
7. Measure baseline + adapter digit prevalence without digit suppression on
   the frozen monitoring subset before training and after every epoch (optional
   update intervals). Save epoch and latest adapter-only checkpoints.

# Defaults and controls

- 1 epoch, train cap 20,000 discovery clips, 50 held-out recording-level clips.
- Decoder `q_proj`, `v_proj`, `out_proj`, `fc1`, `fc2`; rank 8, alpha 16,
  dropout 0.05; `encoder_top_layers=0`.
- LR 1e-4, weight decay 0.01, accumulation 8, grad norm cap 1, warmup 20 updates.
- Max generated tokens 192, minimum rest-match 0.9; natural cardinal and
  no-number preservation targets enabled. Numeric-value gate disabled.
- CUDA student bf16 autocast enabled by default; teacher/evaluation use the
  model's ordinary inference precision. Set `bf16=false` if unsupported.
- Parallel defaults: eight GPUs and global batch 8, reusable teacher cache,
  resumable optimizer/RNG checkpoints. `parallel=false` keeps single-device
  online training and inference-only checkpoints. Neither mode automatically
  selects a best checkpoint; gradient checkpointing is not implemented.

```bash
uv run bw run phase4 '{"cohort_run":"setup_scale-20261106-192355-9dca","epochs":1}'
uv run bw run phase4_evaluate '{"training_run":"<phase4-run>","checkpoint":"epoch-01"}'
```

These commands launch real jobs. Do not run synchronous CLI jobs in parallel
with the API's active GPU jobs (see [validation](/reference/controller-validation.md)).

# Artifacts and monitoring

Under `data/runs/<phase4-run>/` (ignored, never commit):

- `manifest.json`: exact cohort IDs, split file hash, seed, protected recordings.
- `targets.jsonl`: one frozen-base outcome per training sample with acceptance
  reason, baseline and accepted text/token IDs. Targets are cached in memory
  within the legacy online run for reuse and retained here for audit. Parallel
  mode additionally persists a content-addressed cross-run teacher cache.
- `monitor.json`: atomically published stage, epoch/update/progress, elapsed
  time, parameter count, filter counters and latest microbatch loss/evaluation.
- `metrics.jsonl`: update-level latest microbatch loss, LR and gradient norm.
- `baseline.jsonl`, `evaluation.jsonl`, `evaluations.jsonl`: saved monitoring
  transcripts and epoch/step aggregates. No automatic correctness labels.
- `epoch-01/`, etc., and `latest/`: `adapter.safetensors` (A/B only) plus
  `adapter.json` (architecture, base-model identity and training config).
- `checkpoints.jsonl`: available adapter artifacts. Cancellation/failure after
  an update saves `latest`; base modules and requires-grad flags are always
  restored. Legacy serial checkpoints do not contain optimizer state; parallel
  checkpoints also include resumable training state and a committed resume pointer.

The **Phase 4** UI uses `/api/phase4/<run>/monitor` to show live loss/LR plots,
filter counters, progress, unsuppressed digit clip rate and digit mention share,
loop/truncation/empty-output warnings, checkpoint list, logs and cancellation.
`phase4_evaluate` reloads saved adapters on the exact same monitoring IDs;
the UI's Reload & evaluate action produces a separate normal job with summary
metrics and `evaluation.jsonl`/`evaluation.json` artifacts.

# Evaluation limits

Digit prevalence is the style metric, **not accuracy**: omission can reduce
digits too. Keep empty, looping, truncated and total number-mention counts.
Repeated epoch monitoring is a development set, not a fresh final test.
The existing controller confirmation cohort remains unopened for later frozen
adapter confirmation.

Correctness remains sampled in ten-sentence packets with the owner. Existing
assistant review spend is **50/100 sentences**, not a new Phase 4 budget; see
[controller validation](/reference/controller-validation.md). Building/testing
the harness does not consume additional correctness samples. Never equate the
heuristic training label with an immutable human correctness judgment.

# Harness validation (not model-quality results)

CPU tests use a randomly initialized tiny Whisper configuration to exercise
real differentiable loss/LoRA updates, teacher isolation, cached greedy decoding,
adapter save/reload, remainder accumulation and cancellation/base restoration.
API tests cover bounded monitoring histories and concurrent partial appends.
The UI was checked in the browser on desktop/mobile using explicitly synthetic
monitoring data in an isolated data directory/server, not corpus predictions.

A metadata-only dry run on the local established cohort selects **16,112
training clips and 50 monitoring recordings** with confirmation exclusions;
no checkpoint was loaded and no corpus audio was transcribed for that check.
No real-corpus training or extra correctness review was run while building the harness.
